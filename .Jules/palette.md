## 2025-04-10 - AppShell Keyboard Accessibility & Screen Reader Polish
**Learning:** In Next.js components utilizing modern un-styled components or inline Tailwind, relying strictly on `focus:outline-none` creates silent keyboard traps for power users and screen readers unless explicitly countered. Converting semantic block elements (like `div`) to actionable UI items via `role="button"` requires explicit `onKeyDown` handlers (capturing 'Enter' and 'Space') to fully mirror native `<button>` accessibility expectations.
**Action:** Always pair `focus:outline-none` with `focus-visible:ring-2` (e.g., `focus-visible:ring-white/30`) to gracefully manage visual focus. For icon-only actions, standard practice must include `aria-label`, `title`, and `aria-hidden="true"` on the SVG children.
